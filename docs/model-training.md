# Model training register

Every training/retraining experiment for Rawl's music-analysis models must leave a record, including candidates that lose validation and runs rejected for promotion. Adding annotations or features should extend this history, rather than replace evidence from previous runs. `AGENTS.md` makes this an ongoing repository requirement.

The append-only ledger is [`reports/model-training/index.jsonl`](../reports/model-training/index.jsonl). Each entry points to a unique run directory containing `record.json` and compressed JSON snapshots of the model, evaluation, dataset manifest, source code and supplied label files. SHA256 checks identify artifacts, features/source files and inputs. Completed phrase, section, tonic, chromatic-bass and Lakh version-ranking training commands now record automatically through [`record-model-training.cjs`](../scripts/rawl/record-model-training.cjs). Section `fit` also archives all three candidate models before selection/testing; phrase archives include teacher, supervised student and distilled student. The chromatic ranker records when `--save-top` fits and publishes its ranking. Version ranking preserves all six GBDT candidates and separate failure/withdrawal records.

Chord templates, the segmental chord decoder, modulation transition penalties, excerpt alignment and retrieval evidence thresholds are separate hand-designed components. `structurePrior.json` is a retired phrase-length prior, not a trained network. Preserve this distinction when describing results.

## October 7 baseline and experiments

**Phrases, original fit:** 2,764 train / 404 validation / 780 test files, grouped by normalized title and byte duplicates. There are 227 features; labels come from cumulative phrase starts. Each fitted runtime branch has 140 trees, depth ≤4, ≤15 leaves, learning rate 0.07, minimum leaf size 100, L2 2, 128 bins, seed 17, no early stopping. Three cross-fitted teachers use 100 trees each. Distillation weights true labels 80% and teacher targets 20% on drum-present examples. It did not beat the supervised pitched student on validation, so runtime uses the joint teacher with drums and supervised student without drums. Original decoder parameters are length weight 0.8 and boundary bias -2. Original test exact F1 is 0.681, within-one-bar F1 0.853, off-grid exact F1 0.616. The rejected distilled variant's metrics are retained; its original fitted weights were not retained by the old trainer. Future runs archive those weights automatically.

**Phrases, four-bar calibration:** user-requested strong duration prior, with the original trees/schema/split frozen. Command: `/private/tmp/rawl-phrase-training/bin/python scripts/rawl/calibrate-phrase-length.py --promote`. Validation compared shared additional penalties `[2,3,4,5,6]` using 0.65 exact F1 + 0.35 off-grid exact F1; selected **2**, retaining length weight .8 / boundary bias -2 and using probability floor `1e-6`. Model is now `phrase-gbdt-82ebee8f69a8`. Four-bar share rises 92.34% → 95.24% on the reused 780-file test; exact F1 0.681 → 0.671, off-grid F1 0.616 → 0.597. This is a policy/accuracy tradeoff, not a new classifier fit or fresh holdout. All 404 validation files match Python/TypeScript decoding. Run `2026-10-07T08-01-25-255Z-phrases-0ca41330516c-652e27` archives old weights, all five decoder candidates, fixtures, hashes and selection details. Future full fits enforce the same minimum prior via the shared decoder. Detailed evidence is in the linked phrase guide and `reports/phrase-model/length-prior-evaluation.json`.

**Sections:** `/f/` only: 2,441 train / 367 validation / 710 test files, using the phrase dataset's groups. There are 213 features, 18,459 positive spans and 470,312 negatives. Configuration: 100 trees, depth ≤4, ≤15 leaves, learning rate 0.08, minimum leaf size 80, L2 2, 128 bins, seed 29, no early stopping. Compare length only, visual similarity + length, and full beginning/ending events with cadence proxies. Validation selected full with section bias -3 and histogram weight zero. Exact test F1: 0.174 / 0.342 / **0.485** respectively; full precision 0.386 and recall 0.654. Existing candidate-model exports preserve all three variants. The model oversegments; Lakh transfer remains unmeasured. Offline sustain versus browser physical note-offs can change boundaries.

**Tonic:** 246 training titles / 3,058 windows; 27 calibration titles / 340 windows. Targets are saved tonic pitch classes, without mode labels. SHA256 of normalized artist/title modulo 5 = 0 is reserved for test; modulo 7 = 0 among the remainder is calibration. Windows crossing annotated tonic changes are excluded. Five normalized 12-bin groups encode note duration, bass evidence, major roots, minor roots and the last root; rotating them to each tonic yields 60 shared linear weights. Fit 400 full-batch gradient steps, step 0.9, L2 0.001, maximizing softmax likelihood. Calibration searches profile blend `[0, .025, .05, .1, .15, .2, .3, .5, 1]` by accuracy, then temperature `[.05, .08, .12, .16, .2, .3, .4, .6, .8, 1]` by log loss. Selected blend is 0.025 and temperature 0.2. Combined calibration accuracy is 0.550; standalone linear accuracy is 0.667 train / 0.553 calibration. The original harmonic evaluation reports duration-weighted held-out tonic agreement 65.4%, a different metric. The old artifact lacks original input/source hashes and an evaluation-to-artifact hash link; its archived entry is explicitly historical, not a newly reproduced run. Future tonic records include MIDI hashes and the consumed chord spans.

**Chromatic bass:** 11 features; ten standardized, with annotated-key distance used directly. Eight weights are fitted and three additions are fixed. Positive annotations are bags of overlapping detections; explicit negative snippets are weighted 15×, with the top 150 unlabeled comparison passages as hard comparisons. Fit 150 epochs of pairwise logistic ranking loss, L2 0.1, step `0.25 / (1 + epoch / 40)`, and enforce specified weight signs. Fixed weights: minor-third share 0.02, opening-minor plausibility 0.005, annotated-key distance -0.0075. Four folds use a polynomial slug hash modulo four. Normalization uses all candidate feature rows, and the additional fixed factors were manually tuned after the original fit; its cross-validation results are diagnostic. Exact artifact counts/weights/ranks are in the archive. Original training input hashes are unavailable; do not attribute today's label snapshot to that historical run.

## Adding data or features

**Lakh versions:** provisional labels cover 88 train / 31 validation / 17 exploratory test groups, 148 absolute/relative MIDI features. GBDT validation top-1 is 0.403 and test top-1 0.324, with weak gains over simple baselines. Linear training failed its promotion gate; the selected GBDT fit succeeded but its UI deployment was subsequently withheld. All five events, including a report-serialization crash and rerun, remain archived. The later user request enables the same artifact as a **preliminary UI order**, with manually annotated choices taking priority. `node scripts/rawl/index-lakh-version-rankings.cjs --deploy` verified all 10,725 scored MIDI hashes and published the unchanged scores; this did not refit weights, change features/labels, or establish new accuracy. Deployment metadata is separate from the fit ledger. The visual audit of 148 annotated groups / 572 files exposed role, phase, duplicate and label-provenance problems. Its observations are hypotheses, not additional gold labels. See the linked version guide for configurations, baselines, commands and the required fresh holdout.

1. Save human corrections in the ordinary annotation view. The signed-in label export includes curated analyses and that annotator's corrections; inferred previews and other contributors' versions are excluded. Record the snapshot's hash and label provenance. External charts need source URLs, usage constraints, alignment confidence and human acceptance before they become gold labels.
2. Keep prior train/validation/test group membership when extending a dataset. Put duplicates/arrangements in the same group. The current hash splits can change when a new duplicate merges groups; explicitly audit migrations before comparing experiments. Add new material to training/validation first. Use a fresh untouched test set once test disagreements have guided feature design.
3. Name the hypothesis and increment the feature version when extraction, ordering or semantics change. Preserve the feature-name array. Specify targets, negative generation, sample weights, missing-drum handling, timing/sustain representation and any label-derived inputs. Re-export the complete dataset after a schema change.
4. Run controlled ablations on the same split. Select hyperparameters and decoder behavior on validation, then freeze them before test. Preserve unsuccessful experiments and subgroup counts, especially drums, off-grid boundaries and short/long sections. Record the exact command, dependency versions, seeds, loss, configuration and baseline.
5. Archive the candidate and reports, then validate numeric export, runtime/cache versions and affected Chrome behavior before promotion. Latest report paths remain convenience views; the run ledger preserves previous evidence. For training crashes without an artifact, create a `failed` record with the command and error using `recordTrainingRun`; automatic post-fit logging cannot capture a process killed before reaching the logger.

Current trainers **refit from retained labels plus new data**. Exported JSON supports inference, not continuation of a scikit-learn training session. Warm-starting a tree ensemble would require preserving its native training state and an unchanged feature schema; adding/redefining features calls for a fresh fit. No current pipeline silently performs online training from browsing or provisional predictions.

## Reproduction and record inspection

The [phrase](phrase-boundary-model.md#use-and-feedback-loop) and [section](section-boundary-model.md#use-and-retraining) guides contain complete command sequences and the pinned Python environment. Tonic training requires the absolute chord sidecars from an indexing pass:

```sh
node scripts/rawl/train-harmony-key.cjs
node scripts/rawl/search-chromatic-minor-bass.js --save-top
```

Those commands train/write their artifacts; reading existing archives does not retrain anything. Compressed records are ordinary gzip JSON, for example:

```sh
python3 -m json.tool reports/model-training/RUN_ID/record.json
gzip -dc reports/model-training/RUN_ID/evaluation.json.gz
```

Historical snapshots added on October 7 preserve the current phrase, section, tonic and bass artifacts. A historical snapshot's `createdAt` is the **archival time**, not a fabricated training timestamp or command. Missing provenance is stated in its metadata. Source snapshots contain the code at archival time; they are not certified original historical source revisions.
